# Contributing Guide

[English](CONTRIBUTING.md) | [简体中文](CONTRIBUTING_zh-CN.md)

Welcome to contribute to **Sena Repo**. Sena Repo is a visual novel private library manager built with a FastAPI server and a Flutter multi-platform client. It currently targets Windows, Android, and Linux clients plus a Docker server.

Reporting issues, improving documentation, or suggesting features is just as valuable a contribution.

## Before You Start

- Search [Issues](https://github.com/404-GCross/Sena-Repo/issues) first to check whether the same problem or suggestion already exists.
- For larger feature changes, open an Issue to discuss first — especially changes that affect the database schema, client/server APIs, the download protocol, the Steam patch workflow, or release workflows.
- The main development branch is `main`; submit Pull Requests against `main` by default.
- This project covers game library scanning, OpenList file sources, metadata scraping, Steam patch injection, and push downloads to LunaBox / ReinaManager. When changing any of these flows, check whether the client, the server, and the docs need to be updated together.

## Repository Layout

| Path | Description |
|------|-------------|
| `server/` | FastAPI server, SQLite database models, scanning/scraping/download APIs |
| `client/` | Flutter client for Windows / Android / Linux |
| Docs site ([sena-repo.github.io](https://sena-repo.github.io/), source repo `Sena-Repo/sena-repo.github.io`) | Chinese user docs, technical docs, troubleshooting docs, and test checklists |
| `.github/workflows/` | CI, dev pre-release, official Release, and 7-Zip-zstd build workflows |
| `client/assets/binaries/` | Bundled binary archives (`aria2/`, `7zip-zstd/`); CI copies them to flat per-platform paths before packaging |
| `AGENTS.md` | Coding-agent rules and commit conventions for this repository (`CLAUDE.md` is a symlink to it) |

> `client/linux` is not committed. The Linux runner is generated by `flutter create .` in CI and patched automatically via `.github/scripts/patch_linux_runner_touch.py`.

> The repository-root `AGENTS.md` is the single source of truth for project rules and is read by tools such as Codex and Claude Code; `CLAUDE.md` is only a symlink — do not maintain content there separately.

## Reporting Bugs

Please provide as much of the following as possible:

1. The symptom, expected behavior, and reproduction steps
2. Client platform and version (Windows / Android / Linux, package type)
3. Server deployment method (Docker / direct run), version, and system architecture
4. Relevant log screenshots or text
5. Whether OpenList, cloud drives, a proxy, a Steam patch library, or external-manager push downloads are involved

Do not paste passwords, tokens, OpenList credentials, signed download URLs, Authorization headers, or any link that can directly access private resources in public.

## Local Development

### Server

Python 3.11+ is recommended; CI uses Python 3.12 for syntax checks.

```bash
cd server
python -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
python -m pip install -r requirements.txt
python main.py
```

The server listens on `11451` by default. Common environment variables are documented in `server/config.example.yaml` and the docs site's [server deployment](https://sena-repo.github.io/server/) page:

- `SENA_GAMES_PATH`: game library path
- `SENA_DATA_PATH`: database, images, and configuration data path
- `SENA_PATCH_DIR`: Steam patch library path
- `SENA_PROXY`: scraping proxy
- `SENA_BANGUMI_TOKEN` / `SENA_VNDB_TOKEN`: optional scraping tokens
- `SENA_HIKARINAGI_CLIENT_ID` / `SENA_HIKARINAGI_CLIENT_SECRET`: Hikarinagi client credentials
- `SENA_HIKARINAGI_SCOPE`: Hikarinagi API scope, defaults to `catalog:full`

### Client

CI uses Flutter `3.44.8` stable. Use the same version locally to avoid platform-project and analyzer mismatches.

```bash
cd client
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter run
```

Desktop features depend on platform capabilities:

- Windows / Linux: download, extraction, tray, window management, Steam import and patch injection
- Android: download, extraction, APK install; Steam features are hidden
- Linux: the touch-compatibility patch is injected after CI generates the runner; edit `.github/scripts/patch_linux_runner_touch.py` when changing it

## Submitting Code

1. Create a feature branch from `main`.
2. Keep changes focused; do not include unrelated formatting, experimental files, or local design mockups.
3. Update the affected parts of the client, server, schemas, docs, and test checklists together.
4. Use English Conventional Commits for commit messages, for example:

```text
fix: update Hikarinagi metadata scraping
feat: add manual Steam patch rule mode
docs: refresh contribution guide
```

5. In the Pull Request description, explain:
   - What changed
   - Why it was changed this way
   - Which checks you ran
   - Whether it affects the database, configuration, the download protocol, or client/server APIs

## Checks and Tests

Run the narrowest reliable checks for the scope of your change.

### Server changes

```bash
cd server
python -m compileall .
```

For a small number of files you can also use:

```bash
python -m py_compile path/to/file.py
```

When database models, Pydantic schemas, API response fields, or import flows are involved, also check:

- SQLAlchemy models
- Pydantic schemas
- Database initialization / migration compatibility logic
- Flutter client field parsing
- Docs and test checklists

### Client changes

```bash
cd client
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
```

When downloads, extraction, logging, Steam, Android permissions, Linux touch input, or external-manager protocols are involved, verify on a real device for the target platform at least once.

### Documentation changes

Please confirm:

- README, the docs site, and `CONTRIBUTING.md` describe the same behavior
- Workflow names, the Flutter version, Docker image tags, and platform artifacts are not outdated
- Example commands contain no real paths, tokens, or private URLs

## CI and Releases

Main workflows:

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| `.github/workflows/build.yml` | Push to any branch; PRs to `main`, `master`; manual dispatch | Server `compileall`, Flutter analyze, Android / Windows / Linux / Server builds, and publishes the `dev-release` pre-release on non-PR runs |
| `.github/workflows/build_Release.yml` | Manual dispatch | Builds official Release artifacts, publishes a GitHub Release, and pushes Docker images |
| `.github/workflows/build-7zz-zstd.yml` | Manual or maintenance trigger | Builds 7-Zip-zstd binaries for each platform |

The key checks in `build.yml` are:

- `Server checks`: installs server dependencies and runs `python -m compileall .`
- `Flutter analyze`: installs Flutter `3.44.8` and runs `flutter analyze --no-fatal-infos --no-fatal-warnings`

Do not treat a successful full packaging run as a substitute for the analyzer; client changes must explicitly confirm that `Flutter analyze` passed.

## Development Notes

### Client / server protocol

When adding, renaming, or removing API fields, check all of:

- Server request/response models
- Flutter `ApiClient`, data models, and UI call sites
- Defaults and compatibility logic for existing database data
- Related docs and error messages

### Downloads and external managers

The download path may involve local files, OpenList 302 redirects, cloud drives/CDNs, Range requests, signed URLs, checksums, and third-party manager protocols. Pay special attention to:

- Do not proxy large OpenList files through the Sena server by default unless a feature explicitly requires it
- Do not write Sena tokens, OpenList credentials, or signed download URLs to logs
- LunaBox push downloads currently require `size` and `expires_at`; `checksum_algo` / `checksum` must be passed together when present, and neither when absent
- ReinaManager and LunaBox use different protocols; do not assume their fields are identical

### Steam patches

Steam patch features split into client-side local scanning/injection and server-side patch library management/matching. When changing them, confirm:

- Android does not show Steam patch features
- OpenList patch libraries must distinguish local mappings from cloud drives
- Cloud-drive mode must not download a whole archive just to inspect its directory tree
- `patches.json`, manual rules, archive directory trees, and client injection behavior stay consistent

### Security and privacy

- Do not commit real configuration, tokens, passwords, cookies, OpenList credentials, or private download links
- Avoid logging Authorization headers, signed URLs, account identifiers, and external service keys
- Harden the server yourself before exposing it to the public internet; this project is better suited to intranets, VPNs, or controlled environments

## Documentation Sync

If a change affects user-visible behavior, update at least one related document:

- `README.md`
- Docs site: https://sena-repo.github.io/ (source repo `Sena-Repo/sena-repo.github.io`)
